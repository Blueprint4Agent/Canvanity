# 페이지 유형별 일관성

공통 컴포넌트와 단일 CSS 파일만으로 페이지 일관성이 보장되지는 않습니다.
UI 수정 전에 같은 유형의 기존 화면을 찾고 셸·본문 폭·제목과 본문 간격·카드 표면·타이포그래피·버튼 위치·반응형 규칙을 재사용합니다.
참고 이미지는 의도를 전달하지만 기존 앱의 공통 규칙을 대체하지 않습니다. 공통 클래스가 소유할 수 있는 값을 도메인 CSS에 복사하지 않습니다.

| 유형           | 비교 기준                                         | 공통 규칙과 허용되는 차이                                                                                                                                                                                    |
| -------------- | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 설정           | `src/pages/settings/SettingsPage.tsx`의 일반 설정 | 공통 설정 셸·헤더, 기본 행은 `settings-general-content`와 `settings-row`를 사용합니다. 계정은 기존 프로필·사진·삭제 구성을 유지할 수 있습니다. 도메인 내용은 달라도 헤더 배치와 기본 표면은 동일해야 합니다. |
| 인증           | `src/pages/login/`의 로그인·가입·비밀번호 재설정  | 기존 인증 셸, 폼·검증·버튼 위치를 가장 가까운 폼 화면과 비교합니다.                                                                                                                                          |
| 목록·관리자    | `src/pages/admin/`, `notes/collections.md`        | 기존 검색·필터·표·목록·도구 모음·페이지 이동·상태 패턴을 재사용합니다. 열 차이가 새 도구 모음 디자인의 이유는 아닙니다.                                                                                      |
| 모달           | 공통 Modal과 기존 기능별 대화상자                 | 둥근 셸, 고정 헤더·푸터, 내부 스크롤, 포커스와 버튼 규칙을 공유합니다. 도메인 필드만 달라집니다.                                                                                                             |
| 독립 플랜 화면 | `src/pages/billing/PlansPage.tsx`                 | 설정 셸과 구분되는 전체 화면 닫기·스크롤 규칙을 유지합니다.                                                                                                                                                  |

새 유형은 두 번째 화면을 만들기 전에 기준 소유자와 공통 규칙을 이 문서에 등록합니다. 복합 화면은 영역별 유형을 구분합니다.
서로 다른 유형을 무조건 같은 크기로 만들지 않습니다. 예외는 범위와 이유를 기록하고, 공통 규칙 변경은 도메인별 덮어쓰기 대신 영향을 받는 화면에 함께 적용합니다.

## 필수 작업 기록

페이지·컴포넌트·앱 진입/라우팅·스타일 변경은 커밋 제목이 일치하는 작업 기록에 `# Page Family`와
`## Family`, `## Reference`, `## Shared Rules`, `## Exceptions`, `## Evidence`를 작성합니다.
구현 전에 비교 계획을 작성하고 커밋 전에 실제 결과와 테스트·산출물 경로로 갱신합니다.
단순 N/A·TODO·주석·다른 커밋의 기록으로는 통과하지 못합니다. 화면과 무관한 소스 변경은 영향이 없는 이유와 유효한 기존 검증을 명시합니다.
문서·테스트·훅만 바뀌는 경우 이 검토는 필수가 아니며 UI 삭제·이름 변경은 검사 대상입니다.

## 검증과 한계

`make verify-plan`과 `make verify`를 실행합니다. `make ui-composition-check`는 설정 헤더를 도메인 래퍼 안에 넣어 간격이 중복되는 구성을 거부합니다.
설정 헤더는 공통 셸의 직접 자식 또는 셸에 합성되는 프래그먼트 루트에 둡니다. 거버넌스는 같은 인덱스/커밋의 지침과 기록을 읽어 이전 커밋의 정책을 유지합니다.
거부·허용 Python 픽스처는 기본 `make check` 경로에서 실행됩니다.

시각적 변경은 모바일·데스크톱과 밝은·어두운 테마에서 비교하며 긴 번역문, 빈 상태·로딩·오류, 버튼도 해당 범위에 따라 확인합니다.
단순 넘침 검사 외에 브라우저의 실제 치수·계산된 스타일과 스크린샷을 확인합니다.
`tests/e2e/billing.spec.ts`는 390/1440px 양 테마에서 일반/결제 설정의 헤더 간격과 행 폭·패딩·테두리·곡률·배경을 비교하며 한국어 모바일과 등록 상태도 검증합니다.
새 레이아웃은 해당 유형의 비교 검증을 확장합니다.

정적 검사만으로 모든 페이지의 의미상 유형이나 시각적 동일성을 판단할 수는 없습니다. 작업 기록 검사는 기록의 존재를 강제하며 내용의 진실성을 보장하지 않습니다.
브라우저 비교도 등록된 사례만 다룹니다. 새 유형은 검토와 검증을 추가해야 하며 공통 컴포넌트 검사 통과만으로 배치 일관성을 주장하지 않습니다.

서버 연결 오류 화면은 쇼케이스 경로와 같은 메인 `AppLayout` 사이드바 및 공통 PanelCard 타이포그래피와 Button을 사용합니다. 기존 콘텐츠 영역 중앙에 최대 30rem 너비의 패널 하나를 배치하고 공개 네브바와 중첩 경고 카드를 제거합니다. 설정 재시도와 지연 로딩 표시는 기존 상태 소유자가 관리합니다.

키보드 설정은 일반 설정의 행·헤더를 재사용합니다. 두 앱 단축키를 계정별로 변경·복원하고 키 조합 카드를 눌러 편집하고 다른 곳을 누르면 취소합니다. 중복 조합만 거부합니다. 설정 섹션 전환 시 주변 메뉴와 컨테이너 위치를 유지합니다. 기본/캡슐 버튼은 드롭다운과 같은 32px 높이이며 터치 환경은 44px입니다. 프로필 구독 표시는 고정 16px 원과 중앙 정렬 글자를 사용합니다. 홈·관리자 제목은 설정처럼 아이콘을 생략합니다.

프로필 역할 배지는 사진 카드 안에 배치합니다. 옵션 드롭다운은 트리거 왼쪽 끝에서 오른쪽으로 펼치고 화면 경계에서 위치를 제한합니다. 삭제 옵션은 라이트·다크 모두 빨간색입니다. 키보드는 계정 아래에 배치하고 중복 키 안내는 토스트로 표시합니다.

결제 오류와 재시도는 해당 settings-row 카드 내부에 배치합니다. 로딩·오류 상태에서도 결제 카드의 최소 높이를 유지하고 관리자 목록 로딩은 테이블 영역 내부 Spinner로 표시합니다.

## 개인 캔버스와 보드

상단 캡슐 메뉴 Plaza(`/home`), My Canvas(`/my-canvas`), Board(`/board`)가 커뮤니티의 이동을 소유한다. 설정·관리자에서는 이 메뉴를 렌더링하지 않는다. 브랜드는 세션에 기억한 마지막 커뮤니티 경로(검색 상태 포함)로 돌아간다. 세 공간은 동일한 초기 카메라와 제목 좌표를 사용한다. 드롭다운과 계정 설정의 프로필 링크는 독립 `/profile` 편집 화면으로 이동한다. 계정 드롭다운은 클릭으로 열며 메뉴 열기 단축키와 안내는 제공하지 않는다. 기존 단축키 저장 API 필드는 호환성을 위해 유지한다.

CommunityCanvas는 탐색 화면의 격자·카메라·버튼·단축키를 재사용한다. 모든 화면에서 CanvasControls의 좌측 선택·이동 도구와 줌·미니맵을 동일한 위치/동작으로 사용한다. 미니맵은 해당 화면의 실제 DOM 스냅샷이며 언어·테마·프로필 내용 변경 시 갱신한다. My Canvas는 인증 상태의 이름·이메일·사진·소개를 읽고 `/profile` 편집 화면에 연결한다. 프로필 화면은 기존 독립 계열로 유지하며 격자 배경·투명한 편집 트리거와 기존 편집 훅/모달을 사용한다. 공개 공유 기능은 없다. Board는 실제 목록·개설 모달·`/b/{slug}` 기본 홈을 제공한다. 모달은 공용 폼·관심사 선택기(최대 3개)를 재사용하고 주소 중복/저장 실패 시 초안을 유지한다. 기본 홈은 소개·현재 멤버십·기본 Shelf와 실제 게시글 빈 상태를 표시한다. 게시글 작성·회원/등급/Shelf 관리·공식 홈 편집은 후속이며 성공한 것으로 표시하지 않는다.

## 서비스 셸 변형

`AppLayout`/`AppSidebar`에서 사이드바형·상단 메뉴형·미니멀형을 구성합니다. 사이드바 없는 설정·관리자 화면의 하위 메뉴는 `SectionNavigation` 좌측 박스를 재사용하며 전체 상단 메뉴에 넣지 않습니다. 모바일에서는 본문 위 접이식 메뉴로 표시합니다. 스크롤바 공간을 고정하고 설정 컨테이너의 이동 애니메이션을 제거해 전환 중 메뉴 위치를 유지합니다. 홈·프로필·알림의 본문 너비와 표면은 기존 계열을 따릅니다. [레이아웃 모드](layout-modes.md)를 참고하세요.

## 홈 랜딩

`HomePage` / `ProjectOverview`가 홈 랜딩 계열을 소유합니다. 바깥 배경은 전체 폭, 내부 콘텐츠는 최대 70rem이며
1100px 초과에서 소개와 제품 미리보기를 나란히 배치하고 작은 화면에서는 세로로 쌓습니다.
기능 카드와 개발 세 단계, 활용 예시 네 가지를 제공하고 푸터에 제품·자료·계정 메뉴를 모읍니다.
공개 소개 페이지와 제목 타이포그래피·스크린샷 표면 토큰을 공유하지만 설정 카드의 폭과
행 배치는 공유하지 않습니다. MainPageTemplate과 설정 계열은 그대로 유지합니다.
권한 분기는 HomePage, 미리보기 상태는 ProjectOverview가 소유하며 세 셸 모드를 지원합니다.

상단 메뉴·미니멀형은 헤더 안의 텍스트 링크를 사용하고 사이드바형만 떠 있는 캡슐을 사용합니다. 화면·기능·개발 흐름·활용 예시는 기본 앵커로 이동하고 제목이 캡슐 아래 보이도록 간격을 둡니다. 부드러운 스크롤은 동작 줄이기 설정을 따릅니다. GitHub·가이드 아이콘 캡슐은 소개 영역에 배치합니다. 홈 미리보기는 이미지에만 테두리를 두고 브라우저 장식을 제거하며 정적 /about 프레임은 유지합니다. 푸터의 제품·자료·계정 링크는 기존 경로와 권한 조건을 따릅니다. 활용 예시는 확장 가능한 서비스 유형이며 실제 고객 사례를 의미하지 않습니다.

## Minimal Canvas 작업 화면

Canvanity 설정·관리자는 동일한 app-workspace 셸을 사용한다. 데스크톱은 좌측 모던 이미지와 섹션 메뉴, 우측 헤더 및 얇은 구분선 행으로 정렬한다. 모바일은 가로 스크롤 메뉴로 전환한다. 배경은 기존 아이보리/차콜 테마와 희미한 선 격자다. 이 작업 화면에는 카메라 이동이나 줌을 추가하지 않는다. 삭제·결제·보안 모달은 기존 확인 절차를 유지한다.

Button의 canvas 변형은 투명 액션과 은은한 호버, canvas-card는 사진의 작은 확대를 소유한다. 텍스트 액션도 밑줄 대신 같은 강조 규칙을 사용한다. 키보드 포커스는 중립 윤곽선으로 유지하고 모션 감소에서는 확대를 생략한다. Showcase의 Button (canvas actions), Button (canvas-card)가 기본·선택·로딩·비활성 상태의 비교 기준이다. 실제 사진 카드와 설정 아이콘은 이 변형을 재사용하며 페이지마다 호버를 복제하지 않는다. 주요 저장/위험 액션은 기존 Button/ModalButton의 의미와 대비를 유지한다.

설정/관리자 제목은 한글 산세리프를 사용하고 필기체는 브랜드와 Settings/Admin 이미지 캡션에만 적용한다. 데스크톱 메뉴는 본문 스크롤 중 같은 위치를 유지하고 장식 이미지는 목록 위에 둔다. 짧은 화면에서는 장식 이미지를 생략해 메뉴 접근성을 유지한다. 섹션 선택/호버는 공용 ui-action--pencil 질감을 사용하며 Showcase의 Button (pencil menu highlight)에서 비교한다. 드롭다운과 일반 버튼은 질감 없이 파란 호버 배경을 사용한다. 사진 카드의 canvas-card 확대는 높이·너비를 소유하지 않으며 기능의 고정 배치를 덮어쓰지 않는다. 알림/프롬프트 같은 메뉴 없는 보조 화면은 공용 표면·제목을 사용하되 본문 너비는 해당 화면 계열을 유지한다.

일반 텍스트 버튼과 드롭다운 트리거는 얇은 푸른 테두리·8px 곡률·은은한 안쪽 하이라이트를 공유한다. 선택된 컨트롤은 더 선명한 테두리와 파란 표면으로 구분하며 비활성 상태는 호버로 바뀌지 않는다. 캔버스 도구/텍스트 액션은 투명 변형, 사진 카드는 고정 기하와 확대 변형을 사용한다. 공용 토스트는 접힌 종이색/차콜 표면과 명시적인 상태 아이콘으로 표현한다.

기존 pill/pill-secondary 버튼은 캡슐 형태를 유지한다. 공용 외곽선 스타일은 모양을 일괄 치환하지 않고 버튼의 기존 변형에 맞춘 곡률을 사용한다.

블루 버튼의 최종 표면은 부드러운 블루 그라데이션과 흰색 글자다. 로그인 메뉴도 ButtonLink를 통해 같은 변형을 사용한다. 접힌 종이형 토스트는 상태를 명시적으로 받아 중립/성공/오류 아이콘을 구분하며, 상태를 생략한 기존 호출을 성공으로 오인하지 않는다.

사용자가 지정한 연한 블루와 흰색 글자를 최종 팔레트로 유지한다. 해당 채움형 버튼의 색상 회귀 검사는 2.5 대비를 하한으로 사용하며 WCAG AA 충족으로 설명하지 않는다. 일반 본문/투명 액션/토스트의 기존 4.5 기준은 유지한다. 드롭다운 화살표도 버튼 글자색을 상속한다.

## 페이지 전환과 호버 기본 규칙

새 페이지는 AppLayout의 콘텐츠 전환 규칙을 기본으로 따른다. 설정·관리자·프로필·커뮤니티 화면에서 220ms 페이드와 7px 이동을 사용한다. URL 변경 시 DOM을 재마운트하지 않으며 입력/API 상태를 보존한다. 캔버스는 내부 콘텐츠만 움직이고 카메라·선택·이동·미니맵 도구는 고정한다. 새로 마운트되는 지연 로딩 콘텐츠도 같은 진입 효과를 사용한다. 모션 줄이기는 전환과 확대를 생략한다.

큰 제목 아래 짧은 소개 문구는 현재 한국어 UI에서도 영어를 사용한다.

상단 메뉴는 필기체와 lucide 아이콘을 사용하며 호버에서 1.06배 확대만 부드럽게 전환하고 배경은 선택된 메뉴에만 표시한다. 레이아웃 크기를 변경하지 않는다. Plaza/My Canvas/Board의 큰 제목도 같은 필기체와 좌표 배치를 사용한다.

미니맵 대기는 공용 Spinner를 사용한다. 스냅샷은 계정별 AppShell Provider 메모리에 최대 8개만 재사용하며 언어·테마·실제 내용 변경 시 갱신한다. 로그아웃·계정 변경 시 캐시만 교체하고 페이지를 재마운트하지 않는다. 교체된 캐시 소유자와 다른 스냅샷은 즉시 숨긴다. 폰트 임베딩은 앱 수명 동안 재사용하고 DOM 복제 작업은 직렬화한다. 줌/팬이나 프로필 입력 초안은 재촬영하지 않는다.

## 프로필 정체성과 관심사

프로필은 사진·이름·@닉네임·소개·관심사·메타데이터 순서다. 이름·닉네임·소개·위치는 기존 인라인 편집을 사용한다. 닉네임은 한글·영문 소문자·숫자·밑줄 2~24자이며 DB 고유 인덱스로 중복을 방지한다. 비워서 해제할 수 있다. 편집 가능한 항목은 패딩과 은은한 확대를 사용하며 연필 아이콘은 표시하지 않는다.

관심사는 라벨·삭제 가능한 칩·`+ 추가`로 표시한다. 추가 시 검색·선택 모달을 열고 전체 프로필 편집 모달에서도 같은 `ProfileInterestsField`를 사용한다. 공식 관심사만 최대 8개 선택하며 쉼표 자유 입력·신규 생성·제안을 제공하지 않는다. 공식 사전은 API에서 한 번 받아 페이지가 소유하고 기능 컴포넌트에 props로 전달한다. 한글/영문 이름과 동의어로 검색하고 고정 ID를 저장한다. 로딩·오류·재시도·검색 결과 없음·선택 한도를 명시한다. 저장 오류는 선택 초안을 유지한다.

My Canvas는 같은 인증 데이터와 공식 사전의 표시 이름을 사용한다. 프로필 사진·닉네임·관심사 변경은 미니맵의 내용 버전을 갱신한다. 초기 공식 관심사 40개와 관리자 운영·향후 Board/Canvas 자유 태그 경계는 [관심사와 태그 정책](interest-policy.md)을 따른다.
