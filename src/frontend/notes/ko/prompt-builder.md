# 단계별 프롬프트 만들기

[English](../prompt-builder.md)

사이드바·상단 메뉴·미니멀 레이아웃의 홈 다음에 **프롬프트 만들기**가 표시됩니다.
`/prompt-builder`는 기존 AppShell 안에서 지연 로딩되며 개발·프로덕션 모두 비회원과
회원이 사용할 수 있습니다. 기존 설정·서버 연결 확인 경로는 그대로 적용됩니다.

중앙 캡슐 → 기능 추가/프로젝트 시작 후 **이름 → 구현 범위 → 기능·권한 → 완료 방식**
네 단계로 진행합니다. 기본적으로 직접 입력이 필요한 항목은 이름 하나입니다.
범위는 백엔드·프론트엔드·UI 등 12개 카드, 기능은 검색·알림 등 6개 카드에서 복수 선택합니다.
추가 요청은 선택 입력입니다. 필수/선택 표시와 건너뛰기를 제공하며 범위는 하나 이상 골라야 합니다.
실제 배포까지 선택하면 배포 대상 입력이 필수이고, 배포 구성 카드만으로 배포를 허용하지 않습니다.

RBAC 기본값은 비회원 접근 불가, 회원 본인 데이터 CRUD, 매니저 서비스/테넌트 내 조회,
관리자 같은 범위의 CRUD입니다. 역할별 조회·추가·수정·삭제를 각각 변경하고 로그인 역할의
데이터 범위를 본인/전체로 선택합니다. 비회원 허용은 공개 데이터에 한정합니다.
이는 수정 가능한 프롬프트 기본값이며 실제 서비스 권한을 변경하지 않습니다.
결과는 서버 권한 검증과 기존 정책 충돌 확인을 지시하고 UI만 선택하면 백엔드 의존성을 명시합니다.
확인 화면에서 네 항목을 수정할 수 있으며 배포를 해제하면 기존 대상 입력은 결과에서 제외합니다.
기능 미선택 시 이름과 기존 프로젝트를 바탕으로 최소 동작을 정하도록 제안합니다.

결과는 요구사항·범위·저장소 분석·설계·구현·검증·통합을 연결한 한/영 Markdown입니다.
브라우저 클립보드 복사를 지원하며 실패하면 직접 선택하거나 Markdown으로 저장할 수 있습니다.
다운로드는 화면의 지시문과 동일한 UTF-8 `.md` 파일입니다. 이 화면은 모델 호출이나 실제
저장소 분석을 실행하지 않으며 이미 분석·검증을 끝낸 것으로 표현하지 않습니다.
종료점 선택은 지시문에만 반영되고 실제 커밋·병합·배포를 수행하지 않습니다.

단계와 답변은 페이지가 소유하며 두 작업 유형의 답변을 각각 메모리에 유지합니다.
화면을 벗어나거나 새로고침하면 초기화되고 서버 전송·영구 저장하지 않습니다.
새 프롬프트는 확인 후 두 경로를 초기화합니다. 새 상태 저장소·의존성·백엔드 API·실시간 작업은 없습니다.

MainPageTemplate의 설정 계열 셸·너비·제목·모바일 여백과 공통 InputField/TextareaField,
FormCheckbox, DropdownMenu, SelectionCard, 캡슐형 Button, Modal을 재사용합니다. 같은 폭의 선택 카드와 진행 표시,
짧은 전환을 더하고 배경 효과는 가장자리를 마스킹해 클릭을 방해하지 않습니다.
애니메이션 줄이기에서는 배경과 전환을 정지합니다. 단계 이동 시 제목으로 접근성 포커스를
옮기며 실제 버튼·입력의 키보드 포커스 표시는 공통 스타일을 유지합니다.

검증은 단위·컴포넌트의 필수 입력/답변 분리/RBAC/완료 범위 검사와
`tests/e2e/prompt-builder.spec.ts`의 프로덕션 비회원 두 경로·수정·복사·다운로드,
세 레이아웃 메뉴, General 화면과의 390/1440 한글 라이트/다크 비교를 포함합니다.
프로덕션 라우트 검사는 지연 청크와 직접 새로고침을 확인하며 Make 검증 대상에 포함됩니다.

## 플로우 평가

실사용자 조사 결과가 아니라 브라우저 동작과 390/1440 한글 라이트/다크 화면을 검토한 결과입니다.

- 입력 부담: 필수 텍스트는 이름 하나, 필수 선택은 범위 하나입니다. 나머지 두 질문은 기본값으로 진행하며 배포할 때만 대상 입력이 추가됩니다.
- 명확성: 추상적인 사용자 설명을 동작·데이터 권한으로 바꿨습니다. 마우스·키보드 조작과 확인 화면의 수정 내용 반영을 검증했습니다.
- 실행 범위: 해제한 요소와 이전 배포 대상이 결과에 섞이지 않으며 로컬/PR/병합/배포의 종료점을 구분합니다.
- 남은 부담: 질문은 네 단계지만 시작·유형 선택·확인·결과를 포함하면 총 여덟 화면입니다. 기능·권한 화면이 가장 밀도가 높고 모바일에서 세로 스크롤이 필요합니다. 기본값과 건너뛰기로 상세 편집 부담을 줄였습니다.
- 프롬프트 품질: 선택한 기능의 검증 항목과 권한 경계를 자동 구성합니다. 이름만으로 업무 규칙을 확정할 수는 없어 구현 에이전트가 필수 미정 사항을 확인하도록 합니다. 모든 아이디어의 무질문 자동 완성을 보장하는 흐름은 아닙니다.
