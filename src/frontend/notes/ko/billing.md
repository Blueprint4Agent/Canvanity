# 결제 설정과 구독 결제

[English](../billing.md)

프로필 메뉴는 독립 `/plans` 화면을 엽니다. Free·Plus·Pro 카드, 전체 화면 닫기·스크롤,
각 유료 카드의 월간·연간 선택과 작은 통화 선택 구성을 유지합니다. 로그인 사용자는 `useSubscription`을 통해
`GET /billing/plans`와 `/billing/subscription`을 조회합니다. 가격은 서버가 허용한 Stripe
Price의 최소 통화 단위로 내려오며 원화는 소수 단위가 없습니다. Plus 샌드박스 예시는 월간
₩3,990 / US$3.99, 연간 ₩43,092 / US$43.09이며 Pro 가격은 아래 표에 정리했습니다.
각 통화는 환율 환산이 아닌 별도 가격입니다.
비로그인 사용자는 먼저 로그인합니다. 가격이 없으면 구매 가능한 하드코딩 가격 대신
준비 상태를 표시합니다. URL의 선택값은 현재 플랜이나 결제 완료 근거가 아닙니다.

현재 플랜은 서버 조회 결과로 비활성 표시합니다. Free도 조회한 뒤에만 현재 플랜으로
표시합니다. 기존 구독이 있으면 중복 Checkout을 막으며 지원되는 활성 구독은 결제 성공 후 즉시 업그레이드, 기간 종료 시 다운그레이드·취소와 예약 철회를 제공합니다. 월간·연간 결제는 플랜·통화·요청 UUID만
`POST /billing/checkout-sessions`에 전송합니다. 훅은 중복 클릭을 잠그고 실패 재시도에
UUID를 유지합니다. 서버는 기기 간 동시 요청도 고객별 예약으로 묶습니다.
이동 주소는 사용자 정보·별도 포트 없는 HTTPS `checkout.stripe.com`만 허용합니다.

구독 복귀 URL은 `/settings?billing_checkout={CHECKOUT_SESSION_ID}`와
`/settings?billing_checkout=cancelled`입니다. 자동으로 결제 섹션을 열며 소유자를 확인한
상태 API의 `paid=true`만 결제 완료로 표시합니다. complete라도 미결제이면 확인 중으로
표시하고 새로고침으로 재조회합니다. 현재 플랜·상태·갱신/종료일은 구독 API에서 읽습니다.
로컬 이용권 부여나 웹훅 상태 저장은 없습니다. 조회 실패·알 수 없는 구독·연체를 Free로 바꾸지 않습니다.

카드·Link 등록은 설정의 결제 화면에서 기존 `useBilling`과 타입 기반 API를 사용합니다.
`/setup-sessions` 및 `billing_setup` 복귀를 유지하며 `registered=true`만 등록 성공입니다.
페이지 이동·재시도·테스트 모드·비활성/오프라인 처리는 유지합니다. 최근 거래 내역·청구 정보를 Stripe에서 조회하고, 모두 보기는 제한된 고객 포털로 연결합니다. 결제 정보 편집·카드 등록·기본 지정·삭제는 앱 내에서 처리합니다. 구독 Checkout 이력이 있는 계정은 반복 청구가
남지 않도록 운영자 확인 후 삭제할 수 있으며 서버 오류를 번역해서 안내합니다.

두 훅 모두 현재 계정의 조회 상태를 소유하고 오래된 계정/요청 응답을 무시합니다.
계정 변경 시 초기화하고 포커스·온라인·데스크톱 연결 복구 시 재조회합니다.
Billing SSE는 없으며 메모리의 UUID와 별개로 서버가 영속 예약을 소유합니다.
카드 원문이나 인증 정보는 저장하지 않습니다. 네이티브 외부 브라우저/딥링크 복귀는 미구현입니다.

설정은 공통 헤더·본문 간격과 `settings-row`를, 플랜은 별도 유형을 사용합니다.
[페이지 유형 규칙](page-families.md)을 따릅니다. 작은 카드에는 새 memo 경계가 필요하지
않으며 URL·번역·서버 조회 상태가 변경 원인입니다. 계정 전환 경쟁 테스트, 모의 결제
이동/복귀, 유형 간 치수 비교, 프로덕션 지연 로딩을 검사합니다. 모의 검증은 Stripe의 실제 결제 완료를 증명하지 않습니다.

결제·카드 등록 취소 시 공통 토스트를 한 번 표시하고 취소 쿼리를 `section=billing`으로 교체합니다. 다른 쿼리는 유지하며 새로고침이나 포커스 복귀로 알림을 반복하지 않습니다. 결제·플랜·API 키 설정의 로딩은 화면 문장 대신 공통 스피너를 사용하고 접근성 이름을 유지합니다.

서버가 확인한 결제 완료·카드 등록 완료도 공통 알림 팝업으로 표시하고 해당 반환 쿼리를 제거합니다. 대기 상태는 쿼리와 인라인 안내를 유지하여 새로고침으로 완료 여부를 확인하며, 이미 표시한 완료 알림은 포커스 복귀나 새로고침으로 반복하지 않습니다.

설정은 현재 플랜 / 거래 내역 / 결제 정보 / 결제수단 / 플랜 취소 순서로 구성합니다. 묶인 행은 settings-row 표면을 사용하고 작은 더보기 메뉴는 쇼케이스에 등록한 공통 DropdownMenu 변형을 재사용합니다. 현재 플랜은 적용일까지 유지하며 공통 확인 모달이 버전·적용일을 보관하고 성공은 토스트로 표시합니다. 유료 구독의 통화는 유지하며 미지원 구독은 변경을 차단합니다. 도메인 훅이 상세 조회·포털·변경 요청을 소유하고 연결 복구와 계정 변경을 처리합니다. 민감한 카드 입력은 앱 내 Stripe Elements 입력창에서 수행합니다.

등록 카드는 제공된 브랜드·끝 4자리·만료일을 표시합니다. `link` 결제수단에는 지갑 내부 카드 정보가 제공되지 않으므로 공식 Link 로고와 지갑 이름을 표시하며 카드 정보를 임의로 만들지 않습니다. 설정과 결제 활성화 상태의 요금제 화면에는 공식 Powered by Stripe 배지를 표시합니다. 로고는 로컬 파일이며 출처는 `public/payment-brands/README.md`에 기록합니다.

구독 취소는 계정 삭제와 같은 섹션·위험 버튼을 사용하며 Free 전환 확인에도 적용합니다. 예약 변경 취소는 중립 버튼을 유지합니다. 결제수단 목록은 빈 그룹을 제외하며 Stripe 공식 흑백 배지는 선택한 테마를 따릅니다.

결제 페이지 오류는 번역 후 중복을 제거하여 하나의 간결한 안내 영역에 표시합니다. 구독 변경 확인창이 열려 있으면 해당 오류는 확인창 안에 표시합니다. 훅의 오류 상태와 재시도 동작은 유지합니다.

## 앱 내 결제 관리

공통 편집 모달에서 이메일·이름·주소를 `PUT /billing/profile`로 저장합니다. 등록 결제수단의 기본 지정·삭제는 `POST /billing/payment-methods/{id}`를 사용하며 활성 구독의 기본 수단은 대체 수단을 지정하기 전까지 삭제할 수 없습니다. 훅이 중복 요청을 잠그고 실패한 요청의 UUID를 재사용하며 성공 후 실제 상태를 재조회합니다. 상시 새로고침 버튼은 제거하고 오류에만 재시도를 제공합니다. 모달 작업 오류는 해당 모달 안에 표시합니다.

백엔드 환경에 선택 설정 `STRIPE_PUBLISHABLE_KEY`를 넣으면 앱 내 카드 등록이 활성화됩니다. `POST /billing/card-setups`의 카드 전용 SetupIntent client secret은 지연 로딩한 Stripe 입력창 메모리에서만 사용하며 저장·로그에 남기지 않습니다. `GET /billing/card-setups/{id}`의 소유자·모드 확인 결과 `registered=true`만 등록 성공으로 처리합니다. 인증 복귀 시 설정 기본 경로를 유지하고 Stripe 비밀 쿼리를 제거한 뒤 서버에서 다시 확인합니다. 기존 호스팅 등록 API는 호환성을 유지합니다.

공통 `DropdownMenu`의 compact 액션 메뉴는 점 세 개 아이콘과 내용 너비 메뉴를 사용합니다. 우측 정렬·화면 경계 제한·위아래 전환·Escape 포커스 복귀를 공통으로 처리합니다. 항목에 아이콘과 `tone="danger"`를 지정할 수 있으며 결제 페이지는 기본 지정·휴지통 아이콘을 사용합니다. 쇼케이스에서 `DropdownMenu actions`를 검색하면 API 호출 없이 선택·삭제 예시를 확인할 수 있습니다.

### 국가별 결제 주소

공개 키가 설정되어 있으면 결제 정보 편집 창에서 Stripe AddressElement를 billing 모드로 지연 로딩합니다. 국가별 필드명, 지역 선택 목록, 입력 완성도 검증은 Stripe가 관리하며 지역 선택 목록이 없는 국가는 직접 입력합니다. 예를 들어 한국은 도시·시도, 미국은 주, 일본은 도도부현 선택을 제공합니다. 이메일은 기존 InputField를 사용합니다. 저장 시 `getValue()`로 검증된 주소만 기존 프로필 변경 API에 전달하고 선택적 주소란 2의 null은 빈 문자열로 변환합니다. 기존 compact Modal 내부에서 앱의 스타일 토큰을 사용하며 로딩·오류 중에는 저장을 차단하고 재시도를 제공합니다.

주소 편집은 SetupIntent 생성이나 결제수단 입력을 요구하지 않으며 Google Maps 주소 자동완성을 사용하지 않습니다. 공개 키가 없으면 기존 직접 입력 폼을 유지합니다. 이 폼에서도 국가 변경 시 도시·주/도·우편번호를 초기화해 이전 국가의 지역 정보가 남지 않도록 합니다. 모든 국가에 도시 드롭다운이 제공되는 것은 아닙니다.

결제 섹션의 보조 액션은 공통 텍스트 Button과 `section-action-header`를 사용해 해당 제목 옆에 배치합니다. 모두 보기·편집·카드 추가·영수증 액션에 채워진 알약형 버튼을 사용하지 않습니다. 페이지 오류는 현재 요금제 위의 StatusCard 하나에 중복 없이 표시하고 재시도도 같은 영역 안에 배치합니다. 모달 작업 오류는 해당 모달에 유지합니다. 쇼케이스는 텍스트 액션의 기본·로딩·비활성 상태와 StatusCard 재시도 예시를 제공합니다.

## 등급과 결제 주기

요금제는 Free / Plus / Pro이며, Plus와 Pro 카드마다 독립적인 월간·연간 선택을
배치합니다. 통화 선택은 공통입니다. 기존 `monthly`/`annual` 구매 키는 Plus,
`pro_monthly`/`pro_annual`은 Pro로 해석하여 기존 구독과 호환합니다.

| 등급 | 월간 KRW / USD | 연간 KRW / USD   |
| ---- | -------------- | ---------------- |
| Plus | 3,990 / 3.99   | 43,092 / 43.09   |
| Pro  | 11,970 / 11.97 | 129,276 / 129.28 |

위 금액은 구성한 샌드박스 예시이며 화면에 하드코딩하지 않습니다. 연간은 월간
12회보다 약 10% 저렴하며 달러는 센트 단위로 반올림합니다. 카드에 월 환산액,
실제 연 청구액과 서버 가격으로 계산한 할인율을 표시합니다.
`STRIPE_PLUS_{MONTHLY|ANNUAL}_{KRW|USD}_PRICE_ID`는 새 Plus 구매 가격을 선택합니다.
기존 `STRIPE_{MONTHLY|ANNUAL}_{KRW|USD}_PRICE_ID`는 유지하여 이전 가입자의 가격과
등급을 계속 인식합니다. Pro는 `STRIPE_PRO_{MONTHLY|ANNUAL}_{KRW|USD}_PRICE_ID`를
사용하며 미설정 옵션은 구매할 수 없습니다. 각 가격의 모드·통화·주기를 검증합니다.
카탈로그 변경만으로 기존 구독을 새 가격으로 옮기지 않습니다.

Plus → Pro는 `pending_if_incomplete`와 `always_invoice`로 차액 결제가 성공한 뒤
즉시 적용합니다. 동시에 결제 주기를 바꾸면 새 주기가 시작될 수 있습니다.
결제 또는 추가 인증이 남아 있으면 기존 등급을 유지하고 추가 변경을 막습니다.
본인·모드 확인을 거친 Stripe 청구서 링크로 결제를 완료할 수 있습니다. 이 복구
링크는 Stripe를 열며, 이번 작업에서 보류한 앱 내 전체 거래 내역 모달과 다릅니다.
포커스·연결 복구 시 서버를 재조회하며 브라우저가 유료 권한을 임의 부여하지 않습니다.
Pro → Plus, 같은 등급의 주기 변경, Free 전환은 이미 결제한 기간 종료 후 적용합니다.
참고: [Stripe pending updates](https://docs.stripe.com/billing/subscriptions/pending-updates).

라우트 셸이 기존 훅으로 본인의 서버 구독을 조회하고 등급을 레이아웃 props로 전달합니다.
계정 전환 시 초기화하며 사이드바 컴포넌트는 API 훅을 직접 호출하지 않습니다.
역할이나 URL 선택값을 유료 등급으로 해석하지 않습니다. 변경 성공 시 다른 구독
훅에 무효화를 알려 서버를 다시 읽습니다. 미확인·오류를 Free로 표시하지 않습니다.
축소된 프로필에는 접근성 이름이 있는 작은 등급 표시, 메뉴에는 이메일 위의 굵기와
색상을 강조한 전체 구독명을 표시합니다. 별도 상태 저장소·웹훅·사용량 제한 또는
앱 기능별 유료 권한을 이 작업에서 새로 만들지는 않습니다.
