# 서비스 레이아웃 모드

[English](../layout-modes.md)

백엔드 실행 환경변수로 배포 기본값을 선택합니다.

```dotenv
APP_LAYOUT=topnav
```

기존 `/config` 응답의 `app_layout`은 `sidebar`, `topnav`, `focused` 중 하나이며 기본값은 `sidebar`입니다. 환경변수를 변경한 뒤 컨테이너를 재생성하고 브라우저를 새로고침하면 같은 이미지로 세 레이아웃을 사용할 수 있습니다. 잘못된 환경변수 값은 백엔드 설정 검증에서 거부됩니다. `src/service.config.ts`는 이전·연결 불가 제공자 또는 잘못된 응답값에 대한 대체 기본값입니다.

- `sidebar`: 현재의 접기·펼치기 및 너비 조절 가능한 좌측 사이드바입니다. 기존 기본값과 저장된 너비를 유지합니다.
- `topnav`: 서비스 전체 메뉴를 상단에 배치합니다. 좁은 화면에서는 브랜드 왼쪽의 고정 메뉴 아이콘으로 엽니다.
- `focused`(미니멀형): 배경·구분선을 없앤 낮은 헤더입니다. 브랜드 왼쪽의 고정 메뉴 아이콘으로 작은 이동 메뉴를 엽니다. 열어도 아이콘 모양은 바뀌지 않습니다.

개발 모드의 GitHub·사용 가이드·선택적 후원 링크는 헤더 오른쪽에 직접 표시합니다. 프로필·로그인과 데스크톱 연결 상태도 유지하며 아이콘에는 화면 경계를 고려한 툴팁을 제공합니다. 상단의 전체 메뉴에는 홈과 개발용 쇼케이스만 두며 설정·관리자의 세부 항목을 넣지 않습니다.

사이드바가 없는 모드에서는 설정·관리자의 하위 메뉴를 본문 왼쪽 박스로 표시하고, 모바일에서는 본문 위의 접이식 메뉴로 전환합니다. 역할별 노출 조건은 기존과 같습니다. 프로필·알림은 진입한 메뉴 문맥을 유지합니다. 홈·프로필·알림·오류 복구·로그인 오버레이는 기존 페이지 계열 스타일을 유지합니다. 독립 요금제 화면과 공개 소개 페이지는 별도 셸을 유지합니다.

서버 `/config`의 `app_mode`가 명시적으로 `development`일 때만 **설정 → 모양 → 레이아웃**에서 즉시 전환할 수 있습니다. 선택은 배포 경로별 `blueprint_layout_preview` 키로 현재 브라우저에 저장하는 미리보기이며 소스나 배포 기본값은 바꾸지 않습니다. 잘못된 저장값은 서비스 기본값으로 돌아가고 저장소 접근이 차단되어도 현재 세션의 전환은 가능합니다. 운영 모드·설정 로딩·설정 불명 상태에서는 미리보기를 무시하고 선택기를 숨깁니다. Vite 개발 서버 실행 여부로 판단하지 않습니다.

`AppLayoutProvider`가 이 클라이언트 설정을 소유하며 메뉴 열림 상태는 셸 내부에 둡니다. 전환으로 페이지 초안을 다시 마운트하거나 설정 API를 다시 요청하지 않습니다. 계정·인증·권한·실시간 API 계약은 변경하지 않습니다. 배포 기본값은 기존 공통 설정 스냅샷에서 가져오므로 추가 요청이 없습니다. 브라우저 미리보기는 APP_LAYOUT이나 GHCR 결과를 바꾸지 않습니다.

설정 화면은 스크롤바 공간을 고정하고 하위 메뉴 전환 시 컨테이너 이동 애니메이션을 적용하지 않습니다. 공통 본문 너비·표면·컨트롤을 재사용하며 좌측 메뉴 박스만 셸 차이로 취급합니다. `tests/e2e/runtime-modes.spec.ts`에서 저장·운영 격리, 모바일/데스크톱 밝은/어두운 테마, 툴팁, 팝업 경계, 메뉴 위치, 한국어 화면 및 권한을 검사합니다. Provider 테스트는 서비스 기본값·저장소 실패·초안 보존을 확인합니다.

모양의 **서비스 기본값 사용** 버튼으로 브라우저 미리보기를 해제하고 app_layout을 다시 따릅니다. 미리보기 중이 아니면 버튼이 비활성화됩니다. 저장소 접근 실패 시에도 현재 세션에서는 초기화합니다.
