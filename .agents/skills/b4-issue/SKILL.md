# Canvanity 이슈

대상 저장소·AGENTS.md·.github/ISSUE_TEMPLATE을 확인한다. 프런트 이슈도 같은 Canvanity 저장소에 속한다.
기존 양식이 타입·제목 접두사·언어·섹션·권장 라벨의 기준이다.

1. 같은 문제의 열린 이슈와 관련 종료 이슈를 검색하고 읽은 뒤 생성/갱신을 결정한다. 관련 없는 이슈를 닫거나 재개하지 않는다.
2. 버그/기능/백엔드/프런트/문서 중 맞는 기존 양식을 읽는다. YAML frontmatter를 본문에 붙이지 않는다.
   권장 라벨이 실제 원격에 있는지 확인한다.
3. 관측한 문제·요청 동작·범위·검증 가능한 수용 기준을 한국어로 쓴다. 제목은 [type] 한국어 설명이다.
   버그는 재현/기대/실제를 구분하며 모르는 원인·환경은 확인 필요로 남긴다. 실제 파일·로그·관련 이슈를 연결한다.
4. 생성/갱신 요청이면 구조화 본문 또는 UTF-8 --body-file로 게시한다. 초안/리뷰만 요청했으면 준비한 내용만 반환한다.
   이슈 요청만으로 구현이나 PR·다른 사람에게 보내는 메시지까지 범위를 늘리지 않는다.
5. 결과의 제목/본문/라벨/URL을 다시 읽는다. API 결과가 불확실하면 중복 생성 전에 원격 상태를 확인한다.
   구현·검증·게시·main 병합을 구분하고 전체 범위가 완료된 이슈만 닫는다.

파일 변경 없는 이슈 작업에 저장소 커밋/worklog를 요구하지 않는다.
