# Changed File Scope

프런트엔드 셸·프로필·보드·탐색·미니맵·번역·규칙 문서 및 백엔드 사용자 모델·프로필 서비스·0021~0023 마이그레이션·API 계약·생성 타입·검사.

# Reason

개인 캔버스를 메인 메뉴에서 탐색하고, 계정 설정·드롭다운의 프로필 링크는 별도 정보 편집 화면으로 구분한다.

# Design

Plaza / My Canvas / Board 캡슐 메뉴. My Canvas(`/my-canvas`)는 인증 정보의 이름·이메일·사진·소개를 표시하고 별도의 `/profile`에서 기존 서버 편집 흐름을 유지한다. 공통 캔버스 카메라를 재사용한다. 보드는 예시 주제를 Plaza 탐색에 연결한다. 닉네임과 공식 관심사 선택을 프로필 필드로 확장하고 계약/타입을 동기화한다. 공식 사전·동의어·개인 연결을 분리하고 관리자만 사전을 수정한다. 닉네임은 DB 고유 인덱스와 409 도메인 오류를 사용하며 충돌한 갱신은 전체 롤백한다. 0021~0023 마이그레이션은 기존 계정 데이터를 보존하고 기본 빈 관심사를 제공한다.

# Verification Plan

# Impact

/profile 경로 유지. 비로그인 My Canvas는 로그인으로 안내. 게시물 저장·공개 공유는 추가하지 않는다.

# Loop Alignment

프로필은 기존 도메인 훅 → 서버 → 인증 상태 갱신을 유지한다. 공통 UI와 카메라 루프를 재사용한다. 백엔드는 PATCH 라우터 → AuthService → UserRepository → DB/응답으로 닉네임·관심사를 저장한다. 새 실시간·데스크톱 루프는 웹 화면 변경이므로 해당 없음.

# State Ownership

인증은 AuthProvider, 편집은 useProfileEditor, 카메라는 useCanvasCamera, 경로 선택은 Router가 소유한다. 계정 ID에 따라 캐시만 교체하는 AppShell의 CanvasSnapshotCacheProvider가 최대 8개 이미지 캐시를 소유하며 로그아웃·계정 전환 때 폐기한다. 폰트 임베딩만 앱 전역에서 재사용한다.

# Memoization

단순 메뉴/보드 렌더링은 memo를 추가하지 않는다. 카메라의 고빈도 좌표는 기존 ref/RAF를 사용한다.

# Performance Evidence

로컬 Chromium 1440×1000 측정: 기존 재방문 스냅샷 958~1076ms/인코딩 1회. 캐시 적용 후 재방문 41~45ms/인코딩 0회. 최초 새 장면 331~433ms. 별도 개발 서버 측정이며 일반 성능 보장이 아니다.

## 프로필 확장 검증

개인 프로필/마이그레이션 백엔드 검사 18개 통과. 닉네임 초기 마이그레이션 0021 이후 공식 관심사 0022·확장 0023을 적용했으며 현재 버전은 0023(head)다. 브라우저에서 닉네임·태그 저장/재로드/My Canvas 반영 및 409 오류 초안 보존이 통과했다. 투명 편집 버튼의 12px 높이 변화를 측정해 공용 canvas 버튼 패딩과 충돌하는 원인을 확인하고 프로필 편집 컨트롤의 원래 패딩을 명시했다.

## 공식 관심사 최종 범위

자유 입력·개인 관심사·제안은 최종 사용자 결정으로 제외한다. 공식 관심사 40개를 검색하고 최대 8개 선택한다. 전체 편집과 관심사 전용 모달에 동일한 검색·칩 UI를 사용한다. 닉네임은 인라인 편집을 유지한다. Board 공식 관심사 1~3개, Canvas 자유 태그 최대 10개는 후속 구현 기준으로만 기록한다. 디시인사이드·Discord·Pinterest 공식 공개 분류를 참고해 개발 편향을 줄이고 출처를 notes/interest-policy.md에 기록했다. 관리자 API는 공식 사전 추가·이름/동의어/순서 수정·비활성화를 제공하고 고정 ID를 유지한다.

## 커뮤니티 셸 후속 결정

설정·관리자에서는 공간 메뉴를 숨기고 브랜드 클릭으로 세션의 마지막 Plaza/My Canvas/Board 경로에 복귀한다. 세 공간의 제목 월드 좌표뿐 아니라 초기 카메라도 통일했다. 데스크톱 측정에서 기존 Plaza x=104/y=103, My Canvas·Board x=337/y=89였고, 통일 후 모두 x=104/y=103, 63% 배율이다. 계정 ID를 Provider key로 사용하면 인증 지연 때 페이지 전체가 재마운트되는 문제가 있어 key를 제거하고 캐시만 계정별로 교체했다. 지연 인증 중 동일 DOM이 유지되는 브라우저 검사로 확인한다.
